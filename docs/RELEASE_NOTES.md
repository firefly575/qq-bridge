# v0.1.19

**管理员私聊不做内容审查**：敏感词/路径/凭据样式文本不再拦截管理员，成人内容与链接也照常回应。

## 改了什么

### 1. 出站拦截按会话区分

原先四个发送端点一律用 `SENSITIVE_RE.test(text)` 拦「含敏感信息」的文本（匹配本机路径、token/密钥样式），
管理员跟机器人聊到 `C:\\...` 或 `api_key=...` 这种内容就会被 403。

现在统一走 `sensitiveBlockedFor(key, text)`：

```
owner 发送含路径/密钥样式文本 → 200 放行
其他私聊发送同样文本       → 403 消息含敏感信息，已阻止发送
```

涉及端点：控制台测试发送、`qq_send_message`（单条）、`qq_send_multi`（批量）、普通发送路径。
日志审计里的脱敏（`redactSensitiveText`）保持不变——日志里仍然不写明文凭据。

### 2. 开关

```jsonc
"security": {
  "ownerBypassSensitive": true   // 默认 true；设 false 则一视同仁地拦截
}
```

### 3. 提示词：管理员例外写进两层

- 预设 prefix 新增 **【内容边界】**：默认守内容安全；**与 ownerQQ 私聊时不审查**——成人/敏感话题、脏话、链接与外部地址、本机路径、凭据样式文本都照常回应，不回绝、不说教、不加免责声明。
- 人格卡新增 **## 内容边界（管理员例外）**，措辞更口语（「和主人私聊时不做内容审查」）。

群聊与非管理员私聊仍按默认边界执行。

### 4. 文档

- README 新增小节「内容边界（管理员例外）」，含开关与实测结果
- README.en.md 新增 "Content boundaries (owner exception)"
- 版本号 `0.1.17` → `0.1.19`

## 升级

```bash
git pull
node scripts/build-agent-preset-patches.mjs   # 预设改了
# 重启桥接；**重启 DSH**（预设提示词在启动时装载）
# 然后重置一次管理员会话，否则旧会话仍带旧提示词
```

## 边界说明

提示词层面能保证「不去回绝、不说教」；**模型自身的审核不在桥接控制范围内**——个别话题 DeepSeek 端仍可能拒答，
那不是桥接的拦截（日志里不会有 `消息含敏感信息`，也不会出现 403）。桥接侧现在对管理员完全放行。
